# Contributing to OneTomorrow

OneTomorrow is a public civic proposal. You do not need technical experience to improve it.

## Choose the right path

| What you want to do | Where to begin |
| --- | --- |
| Offer your time or share personal details privately | Use the [join form](https://onetomorrow.today/join) |
| Propose a practical step | Open a [guided proposal](https://github.com/colinatwood/onetomorrow.today/issues/new?template=proposal.yml) |
| Correct a claim or source | Open a [correction report](https://github.com/colinatwood/onetomorrow.today/issues/new?template=correction.yml) |
| Report an accessibility barrier | Open an [accessibility report](https://github.com/colinatwood/onetomorrow.today/issues/new?template=accessibility.yml) |
| Provide evidence for a status change | Open a [status update](https://github.com/colinatwood/onetomorrow.today/issues/new?template=status-update.yml) |
| Report a security problem | Email [join@onetomorrow.today](mailto:join@onetomorrow.today?subject=OneTomorrow%20security%20concern) privately |

Public issues and pull requests can be read by anyone. Do not put private, sensitive, or security information in them.

## What a useful proposal includes

Explain the problem, who is affected, the smallest useful first step, evidence, risks, safeguards, a result people can check, and any interest that could influence your view. The guided forms ask for each item.

The [governance policy](https://onetomorrow.today/governance) explains how evidence is labeled and how public decisions are reviewed. The [status page](https://onetomorrow.today/status) distinguishes ideas from active or completed work.

## Sending a code or content change

1. Keep the change focused on one public problem.
2. Write for a reader without specialist knowledge; define necessary technical terms on first use.
3. Preserve the boundary between Today, Tomorrow, Future, and the shared foundation.
4. Run `npm test`, `npm run build`, and `npm run test:a11y`.
5. Complete the pull request checklist, including evidence, risks, owner, and review date.

Maintainers may ask for changes, decline a proposal with an explanation, or close work that has no owner, evidence, safety boundary, or testable next step.
